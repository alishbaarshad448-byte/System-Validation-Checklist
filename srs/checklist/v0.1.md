
# MediTrack SRS Review Checklist

**Version:** 0.1

**Project:** MediTrack Appointment System

**Purpose:** To check the quality, completeness, clarity, and consistency of the SRS document.

## Checklist

| ID | Item | Answer | Evidence | Where question came from |
|---|---|---|---|---|
| C-01 | Does every requirement have a unique identification number? | Yes | R-01 to R-14 have unique IDs. | Document quality |
| C-02 | Does each requirement describe only one action? | No | R-07 includes cancellation, schedule updating, and receptionist notification. | Atomicity |
| C-03 | Are important terms clearly defined in the document? | No | Terms like "active appointments" and "normal working hours" are not defined. | Clarity |
| C-04 | Does the document specify a measurable response time for booking requests? | No | R-02 only says "quickly" without a time limit. | Performance risk |
| C-05 | Does the document specify measurable system availability? | No | R-12 does not define exact working hours or availability percentage. | Reliability |
| C-06 | Are all conflicting requirements resolved in the document? | No | R-04 says appointments last 15 minutes, while R-05 allows 10 to 30 minutes. | Consistency |
| C-07 | Does the document explain how simultaneous booking requests will be handled to prevent double bookings? | No | R-03 says double bookings must be prevented but does not explain simultaneous booking handling. | Double-booking risk |
| C-08 | Does the document specify the number of users or booking requests the system must handle during peak hours? | No | No peak-load limit is mentioned, especially for busy Monday mornings. | Performance risk |
| C-09 | Does the document specify when appointment reminders must be sent? | No | R-06 says reminders will be sent but does not specify the timing. | Missed appointment risk |
| C-10 | Does the document clearly define the cancellation deadline? | No | R-07 allows cancellation "at any time" without explaining the rules. | Cancellation risk |
| C-11 | Does the document specify which users can access patient medical records? | No | R-09 says records must be secure but does not define access permissions. | Patient privacy / DPO |
| C-12 | Does the document specify how patient information will be protected? | No | R-09 does not mention encryption or other protection methods. | Security risk / DPO |
| C-13 | Does the document allow receptionists to book appointments for walk-in patients? | Yes | R-10 directly mentions receptionist booking for walk-in patients. | Receptionist |
| C-14 | Does the document define how emergency walk-in patients will be handled? | No | R-10 mentions walk-ins but does not explain emergency priority. | Emergency patient risk |
| C-15 | Does the document allow doctors to view their daily appointment schedules? | Yes | R-14 directly provides this functionality. | Doctor |
| C-16 | Does the document allow doctors to configure appointment lengths within the stated range? | Yes | R-05 allows doctors to set appointment lengths between 10 and 30 minutes. | Doctor |
| C-17 | Does the document allow patients to book appointments online? | Yes | R-01 directly provides online booking. | Patient |
| C-18 | Does the document provide an alternative booking method for elderly patients who cannot easily use online booking? | No | R-01 focuses on online booking and no alternative support is specified. | Patient / Accessibility risk |
| C-19 | Does the document define the clinic administrator's responsibilities and permissions? | No | No requirement describes administrator functions or permissions. | Clinic administrator |

## Checklist Evaluation Rules

- Yes = The requirement is clearly addressed.
- No = The requirement is missing, unclear, or incomplete.
- N/A = The question does not apply to the document.

**Note:** Every checklist question follows the AOUT rules:

- A – Atomic
- O – Observable
- U – Unambiguous
- T – Traceable
